Graph-RAG knowledge base for AI agents

TMBThanachart Bank · Customer onboarding

Problem
Incident diagnosis, onboarding and impact analysis across 30+ microservices relied on scattered specifications, and AI assistants would answer without evidence.
My contribution
I structured 1,000+ Markdown specifications (services, 100+ database tables, activity logs) into a Graph-RAG knowledge base. I wrote a Python generator for a two-level service and endpoint dependency graph. I also wrote the agent instruction framework (guardrails, task routing and a confidence model), so GitHub Copilot and Claude answer only from traceable evidence. On top of that I built reusable skills: flow tracing, impact analysis, comparing logs against the specs, API contract linting, Liquibase changeset generation and automated merge-request review against the specs.
Outcome
Incident diagnosis, onboarding, impact analysis and migration scripting are faster, and agent answers are grounded in cited specifications rather than guesses.

Release automation for 30+ microservices

TMBThanachart Bank · Backend / DevOps

Problem
Releases and cut-offs across 30+ Spring Boot services on GitLab, Jenkins and AKS involved repetitive manual steps, and slow pipelines held up delivery.
My contribution
I built a Python toolkit that bulk-updates repositories and merge requests, triggers Jenkins image builds and AKS deployments in bulk and verifies each one, and generates daily cut-off reports for 3 squads. I built a pipeline benchmark that times tests, SonarQube analysis and Docker builds, and used it to find speed-ups such as the Gradle configuration cache. I cut Docker build-context size with .dockerignore. I also built a Docker Compose local environment (PostgreSQL, MongoDB, Redis, Kafka) with mock downstream APIs for end-to-end testing.
Outcome
There is less manual release and cut-off work, and build, deploy and code-update steps are consistent across 30+ services.

My contribution
